# hyprcage desktop control: rulings

One line per ruling made during the build, in the format of the sub-project A rulings file.

- Ruling: task 1 check 1 (toplevel export of a hidden window) moves to task 3 step 4 — the frame opcodes differ from screencopy, so a probe needs the generated bindings — cost if wrong: task 3 finds the gap later and the spec gets amended then.
- Ruling: the desktop pointer takes its absolute-motion extent from the logical layout in `hyprctl monitors` (width/scale, height/scale, over all monitors), not from `wl.Client.OutputSize` — `OutputSize` returns 960x540 on the human's 1920x1080 at 1.5 — cost if wrong: pointer clicks land at the wrong place on the real desktop; the final report asks the human for one real-desktop click check.
- Ruling: the desktop AT-SPI source always adds the window's `at` position — GTK3 and Qt give window-relative extents on Hyprland (task 1) — cost if wrong: offsets double for an app that gives screen extents.
- Ruling: notification tests run in `dbus-run-session` with swaync on the nested instance, and `HYPRCAGE_NOTIFY_FILE` overrides the store path — no test notification may reach the human's screen or file — cost if wrong: one more env variable.
- Ruling: `notify_act` without `action` calls `CloseNotification` on `org.freedesktop.Notifications` (the spec's choice), not swaync's own `CloseNotification` — the freedesktop call works with any daemon — cost if wrong: none.
- Ruling: task 8 measured the resting footprint of `hyprcage notifyd` at 12364 KB RSS and 0 s CPU after 60 s, in `dbus-run-session` with swaync on the nested instance — within the spec's 10–15 MB hypothesis — cost if wrong: none.
- Ruling: `hyprcage notifyd` records every `NotificationClosed` signal as it comes; swaync emits the signal twice for one close, so the file can hold two `closed` entries for one ID — cost if wrong: task 9 deduplicates when it reads.
- Ruling: `hyprcage setup` installs the unit from a copy that `contrib/contrib.go` embeds in the binary, because a binary from a release has no checkout to copy from — cost if wrong: one small Go file in `contrib/`.
- Ruling: `tests/nested-hypr.sh` adds a headless output `HC` at 1920x1080 scale 1.5 and disables the host-window output `WAYLAND-1` — task 3 found that the host window's output never renders on the hidden special workspace, so screencopy stalls; the headless output renders and matches the human's monitor — cost if wrong: none.
- Ruling: the pointer-extent hypothesis is verified on the nested headless output at scale 1.5 — `OutputSize` gives 960x540, and `motion_absolute` to (300,200) with that extent lands at (400,266), which is proportional over the logical 1280x720 layout. The desktop pointer sends logical coordinates with the logical layout as the extent — cost if wrong: none.
- Ruling: the cursor restore keeps `follow_mouse = 1` effects — the human's instance has `input:follow_mouse = 1` (read 2026-09-30), so the restore gives focus back to the window under the human's cursor, usually the one the human worked in; a pointer click moves focus anyway under decision 3 — cost if wrong: one focus change per pointer action.
- Mistake (controller): commit 496b5ca deleted `cmd/hyprcage/main.go`. Assumed: `cmd/` held only the throwaway probe `cmd/zz-probe`, so `rm -rf cmd` was safe. True: `cmd/hyprcage/main.go` lives there, and a later `git commit -a` staged its deletion. Evidence: the task 6 implementer could not build the binary. Fixed in a8efc0d. Rule: probes go under /tmp, never inside the repo tree.

## Verification on arjun-e16 (openSUSE Tumbleweed, 2026-09-30)

- Finding: zypper installs `tesseract-ocr` and `tesseract-ocr-traineddata-eng`. The name `tesseract-ocr-traineddata-english` in `install.sh` resolves as a capability of `-eng`. The English data is at `/usr/share/tessdata/eng.traineddata`, the path that `install.sh` checks — cost if wrong: none.
- Finding: openSUSE does not install `at-spi2-core` with GTK, so `org.a11y.Bus` is not activatable and doctor warns. `install.sh` now installs `at-spi2-core` on both distributions (same package name and service file on Arch) — cost if wrong: one package.
- Finding: `tesseract-ocr` 5.5.3-2.1 (openSUSE, 2026-09-23) crashes in `TessBaseAPI::End` after it writes its output. Its backport of CVE-2026-88053 removes the loop that sets `TempConfigFor(this, i) = nullptr` in `ADAPT_CLASS_STRUCT()`, but omits the `std::array` change that upstream uses to initialize the pointers. The crash reproduces in a clean `opensuse/tumbleweed` container and not with Arch's 5.5.3 — cost if wrong: none.
- Ruling: the OCR source accepts the output of a tesseract that a signal killed, when the output starts with the TSV header. The file output of the same crashed run is identical to its stdout and ends at the bottom row of the screen — cost if wrong: a crash in the middle of the output loses the rows after it.
- Ruling: `FindAuto` retries a `no_source` error from a read, as it already did for a `no_source` error from choose. An app that is not yet on the a11y bus makes auto pick OCR, and one failed OCR read ended the poll — cost if wrong: a source that always fails costs the whole timeout before the error.
- Mistake (e16 session): `tests/e2e-desktop.py` replaced the human's a11y socket. Assumed: `dbus-run-session` isolates the a11y bus. True: `at-spi-bus-launcher` puts its socket at `$XDG_RUNTIME_DIR/at-spi/bus`, and the D-Bus-activated launcher inherits the human's `XDG_RUNTIME_DIR`. Swaync is a GTK app, so it activates the launcher first. Evidence: the socket file changed during a run, and a connect to it was refused while the human's broker still listened. Fix: the script starts the launcher itself with a private runtime dir before swaync, and stops if the address is not under that dir. To verify: the same happens on archMachine.
- Finding: `at-spi-bus-launcher` and `at-spi2-registryd` are in `/usr/lib` on Arch and in `/usr/libexec/at-spi2` on openSUSE. The E2E script looks in both — cost if wrong: none.
- Finding: the smoke rows for thunar and wireshark pass through AT-SPI here. The e16 has `input:follow_mouse = 2`, and the E2E pointer steps (e, f) pass with it. `tests/nested-hypr.sh` uses the Lua path — cost if wrong: none.
- Ruling: the e16 does not install the plugin. `~/.claude/skills/hyprcage` is a symlink into the checkout, and the user-scope MCP server runs `~/.local/bin/hyprcage`, so the plugin would register both a second time — cost if wrong: the e16 misses a plugin-only file.

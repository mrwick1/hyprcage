# 2026-09-29

## Design spec for the computer-use fork

Documented the full design for bringing computer use to Hyprland agents. The spec covers agent screens (hidden, silent input and capture), control of the human's desktop (with accepted keyboard-focus blips), and a waybar menu to list agent screens. Success criteria include screen creation, Chrome automation via Chrome DevTools Protocol, recording to MP4, clipboard/file I/O, and desktop window control. Spike on 2026-09-29 confirmed that the base (hexadecimil/hyprcage fork) works on arjun-e16 with Chrome on an agent screen, screenshots under lock, and no disruption to the human's focus. Architecture divides into the fork itself (adds record/clipboard/file/browser/desktop tools in Go), Chrome control (reuses chrome-devtools-mcp with fixed `--browserUrl`), and a waybar module. Portability addressed by moving machine-specific config to `~/.config/hyprcage/config.toml` and teaching the installer both zypper and pacman. Testing plan includes upstream tests, go tests for each tool, smoke script on both machines, and browser E2E with DevTools MCP visible in the mirror. Status: design approved in conversation, waiting for spec review before implementation.

## Recording frame loop and config

Implemented `internal/record/` to handle screen/desktop capture → ffmpeg pipeline. `Loop()` captures frames on schedule, writes raw RGBA to ffmpeg's stdin, and handles timing drift by repeating the previous frame if capture falls behind. Encoder selection (libx264, libopenh264, fallback mpeg4) handles distro differences; scale filter rounds dimensions to even numbers for yuv420p. Added config fields for recording directory (`~/Videos/agent`), max duration (30m default), fps (10 default), and browser settings (Chrome binary, DevTools port 9222). Config parsing reads toml `[record]` and `[browser]` sections with validation (fps ∈ [1,60], port ∈ [1024,65535], max ≥ 1s). Helpers: `ExpandHome()` substitutes `~/` with home directory, `FFmpegArgs()` builds the command line. Tests cover config defaults, overrides, validation boundaries, and frame expansion. Ready for integration with screen capture once wl.Client is available.

## Recording state and MCP integration

Completed the recording control plane: `internal/record/state.go` and `state_test.go` track live recorder PIDs in json files under the registry dir. `Start()` spawns the recording subprocess detached and waits for its state file to confirm startup. `Stop()` sends SIGTERM to the PID and returns the MP4 path (file size included if available). `Load()` and `List()` validate PIDs with `syscall.Kill(pid, 0)` (lightweight check, no signal sent) and clean up stale state files automatically. Integrated into the MCP server as `record_start` and `record_stop` tools in `server_fork.go`; `record_start` dispatches to the running binary with `_record target out` arguments (the CLI wrapper runs the frame loop and manages ffmpeg). Desktop recording locked when session is locked via `lockedFn` callback (task 7 will wire it to `desktop.Locked()`). Live tested on arjun-e16 (Hyprland 0.56.2): 5 s kitty screen at 10 fps produced h264, 1280×800, 51 kB; desktop 3 s produced h264, 1920×1200, 31 kB. Bitrate measurably lower than intended (51 kB/5s vs ~300 kB/s at q=18), hypothesis: ffmpeg default crf is high (around 28), will tune in task 9.

## Desktop operations: list, focus, move, type, key

Implemented task 7: agent control of the human's windows through Hyprland IPC. Package `internal/desktop/` exposes five operations via CLI and MCP tools. `Windows()` lists all clients except hyprcage mirrors. `Focus()`, `Move()`, `Type()`, and `Key()` all validate input (strict address format `0x[0-9a-f]+`, checked rune-by-rune for type operations, key modifiers parsed from `ctrl+shift+...` syntax), check the desktop lock status via `Locked()` (reads `/proc/*/comm` for hyprlock), and bail if the desktop is locked. `Type()` maps each character through `KeyFor()` (hardcoded US layout with shifted pairs like `{` → SHIFT+bracketleft) and rejects unsupported runes with a clear error. `Key()` parses modifiers and key names, validates key names against `[A-Za-z0-9_]+`, and rejects bad modifiers; `ParseCombo()` is testable standalone. Input rejection is strict: a single unsupported character in a type operation aborts without sending anything, avoiding partial input. All operations use `send_shortcut` which Hyprland documents as "moves the focused window out of the way, sends the key to the target, and focuses back" — the human accepted this focus blip on 2026-09-29. Tests cover character mapping boundaries (a-z, A-Z, 0-9, symbols), combo parsing, address format, and lock detection. No tests yet for the e2e CLI or MCP integration; integrations (focus blip, Hyprland uptime) are live-tested only.

## Recording state registry isolation

Moved recording state files from the flat registry directory (with `rec-<target>.json` naming) into a `rec/` subdirectory. This prevents `registry.List()` (which enumerates screens) from reading recorder state files as screen entries. `StatePath()` now returns `registry.Dir()/rec/<target>.json`; `List()` globs the `rec/` subdirectory and parses filenames directly. Added `os.MkdirAll()` in `save()` to create the `rec/` directory on first write, and verified the isolation with a new test that confirms a saved recorder is not visible to `registry.List()`.

## Chrome on agent screen with DevTools

Implemented `internal/browser/` to launch Chrome on the agent's screen with Chrome DevTools Protocol on 127.0.0.1. `Find()` searches for google-chrome, google-chrome-stable, chromium, chromium-browser in order, respecting a config override. `Args()` builds the Chrome command line: `--ozone-platform=wayland` for Hyprland, throwaway profile with `--no-first-run`, and `--remote-debugging-address=127.0.0.1` (isolated, not 0.0.0.0). `Ready()` polls the DevTools version endpoint until Chrome is listening, returning the WebSocket endpoint for agent-chrome MCP tools. `Open()` validates that nothing is already using the port (refuse to share), launches Chrome with screen.Launch, and waits up to 20 seconds for readiness. CLI wrapper `hypercage browser [screen] [url]` dispatches via the binary, returns Info struct with screen, PID, port, browserURL, and WebSocket endpoint. MCP tool `browser_open` wired into `server_fork.go`. Tests cover binary discovery (configured > google-chrome > chromium fallback), command-line args assembly (Wayland, profile, debugger flags, URL), DevTools availability polling (timeout, success, JSON parsing), and port collision detection. Design keeps DevTools accessible only to localhost (security: prevents network exposure) and uses a fresh profile (isolation: no caches, history, or extensions). One Chrome per agent screen; closing the screen closes the browser.

## Launch: DevTools port per screen and port reuse

Implemented a two-step DevTools acquisition flow for `app_launch`: `PrepareDebug()` finds a free port (or fails with CodeLimit if the screen already runs a live application on a saved port) and returns debug args; `ConfirmDebug()` waits for the DevTools endpoint and saves the port to the screen registry. This separates preparation (run before Launch) from confirmation (run after Launch succeeds), preventing the registry save from blocking if DevTools startup fails — the application keeps running and can be debugged later. The pattern also handles dead ports: a saved port that no longer answers is replaced silently (one 200 ms check per prepare). Refactored `internal/browser/Open()` to wire this flow: it now saves the port on successful Ready, not on launch return, so a Chrome that started but failed to debug gets cleaned up without persisting a stale port. Tests added for live-port rejection (CodeLimit) and dead-port replacement (new port is allocated and added to args). Ready for E2E testing with the perception agent.

## CDP error propagation and frame coordinate translation

Refactored `internal/perceive/cdp.go` to propagate CDP protocol errors correctly and compute node positions relative to the page viewport. Key changes: `cdpError` now wraps protocol-level failures (nodes with no layout, missing frames, browser errors) as a distinct type with Code and Message fields; `isProto(err)` distinguishes protocol errors from transport failures (socket resets, timeouts). `Nodes()` now fetches bounding boxes in parallel using `golang.org/x/sync/errgroup` instead of sequential DOM calls, speeding up snapshots with many targets. Frame offset computation (`origin()` and `place()` helpers) translates node centres from target CSS pixels to page pixels by reading the frame owner's bounding box. Each session tracks its target type (page/iframe/webview) via a new `typ` field, enabling `Reveal()` to validate keys without explicit frame lookups. Targets that fail to snapshot (broken viewport eval, missing trees) are detached and skipped, but do not fail the entire `Nodes()` call if other targets succeed; the session stores the first failure and returns it when all targets are tried. Added `golang.org/x/sync v0.20.0` to dependencies. Tests cover box fetch failures (CodeStaleRef vs CodeCDP based on error type), iframe offset computation with frame owners, and skipping of broken targets while returning nodes from live targets. No changes to the key format or wire protocol; this is an internal refinement to error handling and coordinate systems.

## OCR source: tesseract integration

Implemented `internal/perceive/ocr.go` as the fallback source for applications with no accessibility tree. `NewOCR()` creates an `ocrSource` that calls tesseract with `LANG=eng` on a screen snapshot, parsing the TSV output into nodes with names, coordinates, and roles set to "text". The parser merges words of the same (block_num, par_num, line_num) with confidence ≥60 into a single node, positioned at the centre of the union of word bounding boxes. `Nodes()` returns an in-memory cache; `Reveal()` looks up keys in that cache, and `Press()` returns "unsupported" (OCR sees text, not clickable elements). Added setup package fields to detect the OCR installation: `Package` struct now includes a `File` field to check file presence (e.g., `/usr/share/tessdata/eng.traineddata`), and `Missing()` now validates both binary presence and file existence. Updated `install.sh` and `InstallArgv()` to handle distro name differences: pacman's tesseract-data-eng becomes tesseract-ocr-traineddata-english on zypper, mapped via `zypperNames` lookup. The installer discovers distros via presence of pacman or zypper, then maps names before passing to the PM. Tests validate parsing (word merging at low confidence, key sequencing), distro-specific package names (pacman vs zypper), and file existence checks. Ready for end-to-end testing with snapshots of applications without accessibility trees (e.g., Zed).

## AT-SPI tree reader with PID filtering

Implemented `internal/perceive/atspi.go` to read GTK and Qt application accessibility trees over D-Bus AT-SPI protocol, filtered to the screen's processes. `NewATSPI()` connects to the session's a11y bus (via `org.a11y.Bus.GetAddress` redirect) and wraps it with PID filtering: `atspiSource.Nodes()` calls `Walk()` to read the full tree, then keeps only objects whose PID is in `screen.ScreenProcesses(screenName)`. `atspiRoles` maps AT-SPI role names to ARIA-style role names (button family to `button`, entry variants to `textbox`, etc.); other roles keep their AT-SPI name with spaces replaced by underscores. `atspiStates` maps AT-SPI state nicks to Node states (focused, checked, expanded, selected, required, invalid). Hidden widgets in GTK3 appear as `(-2147483648, -2147483648, 1, 1)` in window coordinates; the code treats this as `w <= 0` to set `Offscreen = true`. Node centre (X, Y) is computed from bounding box centre. `dbusTree.Walk()` starts from the root of each on-screen application (identified by PID match to registered D-Bus connection), depth-first-traverses children on the same bus, and stops at `maxObjects=5000` objects per walk. `Reveal()` scrolls to the object (Component.ScrollTo with scrollAnywhere), then re-walks the tree to find the updated coordinates; `Press()` invokes the default action (Action.DoAction index 0). `Scroll()` and `DoAction()` D-Bus calls use `coordWindow` coordinate system (window-local, not screen-local). `HasApps()` checks whether the screen has any AT-SPI applications without allocating a full source. All D-Bus operations use 2-second timeout per call; connection to the a11y bus uses 5-second timeout with context. Tests cover PID filtering (foreign PIDs are excluded, duplicates de-duped by key), role mapping (ARIA names and tree-cell-in-tree detection for table_cell → treeitem), and state decoding (state bits 4, 7, 8, 10, 12, 23, 24, 33, 36 map to checked, editable, enabled, expanded, focused, selected, sensitive, required, invalid-entry). Fixture data loaded from `testdata/atspi_thunar.json` (Thunar file manager snapshot). Added `github.com/godbus/dbus/v5` to dependencies. Tree reader is ready for integration with the agent's perceive loop.

## AT-SPI: connection lifecycle and error tightening

Fixed AT-SPI connection management and error categorization. The a11y bus connection must persist across multiple `Nodes()` calls within a session — it should not be closed when the context expires (the earlier pattern `dbus.Connect(addr, dbus.WithContext(ctx))` caused this). Changed `dialA11y()` to call `dbus.Connect(addr)` directly without the context wrapper; the connection is managed separately by the source's `Closer` function.

PID filtering refactored: `Walk()` now accepts pids as a parameter so PID list is fetched once per walk, not twice (once in `Walk()` and again in the deduplication loop). `apps()` and `Walk()` receive the filtered PID list directly from the caller, eliminating the per-call closure invocation.

Error categorization tightened via new `errRefused` constant and `ok()` helper. Scroll and DoAction methods now detect false return values and map them to `CodeUnsupported` (the object refused). `actErr()` also maps D-Bus errors `UnknownMethod` and `UnknownInterface` to `CodeUnsupported` (method not implemented on the object), distinguishing them from stale references (which map to `CodeStaleRef`). Tests added for unknown state (element with `GetState` failure), action failures (refused, unknown method/interface), and live AT-SPI reading (new test `TestATSPILive` verifies against a real Thunar window when `HYPRCAGE_LIVE_ATSPI` is set). Added `NoStates` flag to track objects that failed `GetState`, preventing false inference of disabled/readonly states when states are unknown.

Connection now lives for the session, not the context. Error handling distinguishes protocol errors (object's app failed) from transport errors (bus connection broken). Live testing ready via environment variable.

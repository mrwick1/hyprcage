# 2026-09-30

Published the hyprcage fork as hyprcage-mrwick1 marketplace. Updated `.claude-plugin/marketplace.json` to list hyprcage-mrwick1 as the canonical marketplace URL, bumped version to 0.4.0 in plugin.json, and updated README. The MCP launcher binary is already built from this checkout, so the version bump does not cause marketplace downloads to replace the local binary.

Added four devtools tools (eval, console, trace, heap) to read page internals from any screen launched with `debug=true` or opened via `browser_open`. Changed the DevTools port assignment from a single fixed config value to per-screen: each screen picks a free 127.0.0.1 port at browser open time, eliminating port collision and the need to manually register agent-chrome MCP once per machine. Refactored browser opening to call a port allocator and check port ownership instead of checking if a port is free. Removed `browser.port` from config validation and the template; kept the file field to allow older config files to load without error. Added a new `internal/cdp/` package for Chrome DevTools protocol client over websocket with flattened sessions (no per-target session tracking). Added `internal/devtools/` with the Session type and the four tools, plus tests. DevTools tools check that the port is still held by the process that opened it, guaranteeing they never reach the human's own Chrome.

Bumped plugin version to 0.5.0 to invalidate the cached 0.4.0 plugin on machines running the skill, forcing a refresh that picks up the devtools tools.

Wrote the design spec for sub-project B (hyprcage desktop control), which lets an agent drive the human's Hyprland desktop with the same text-first tools as on an agent screen. The spec covers three categories of desktop tools: perception (screenshot/snapshot/find on windows), action (click/scroll/drag with pointer restore), and notifications (list/wait/act on swaync). Key decisions from a spike: perception uses a three-tier fallback (AT-SPI, Chrome DevTools protocol if a port is owned, OCR); actions restore cursor position after each op and refuse while hyprlock runs; notifications are kept for 48 hours in a jsonl log by a systemd user unit. The spec plans for E2E to run on a nested Hyprland on a hidden special workspace, proven reachable by verifying wlroots protocol support (`hyprland_toplevel_export_manager_v1`). Existing constraints from the spike: no third-party Wayland compositor offers xdg_wm_base version 6 or higher (Hyprland needs 6), so the nested instance must be Hyprland itself.

Broke the implementation into eleven tasks: verify hypotheses and set up nested Hyprland (task 1); add the desktop target and instance override (task 2); toplevel export and desktop screenshot (task 3); pointer management with cursor restore (task 4); window finding on desktop (task 5); AT-SPI text insertion (task 6); notifications daemon (task 7); action tools (click/scroll/drag/wait/act); batch for desktop (task 9); refactoring the screen driver (task 10); and E2E (task 11). Each task specifies the files to create/modify, test structure, interfaces and review focus. Task 1 is prerequisite-free and produces facts; tasks 2–11 chain with explicit dependencies. All tests pin the review focus areas: cursor restore on error, active workspace isolation, ref separation, AT-SPI coordinate transforms, and notification file durability.

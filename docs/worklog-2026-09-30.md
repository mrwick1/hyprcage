# 2026-09-30

Published the hyprcage fork as hyprcage-mrwick1 marketplace. Updated `.claude-plugin/marketplace.json` to list hyprcage-mrwick1 as the canonical marketplace URL, bumped version to 0.4.0 in plugin.json, and updated README. The MCP launcher binary is already built from this checkout, so the version bump does not cause marketplace downloads to replace the local binary.

Added four devtools tools (eval, console, trace, heap) to read page internals from any screen launched with `debug=true` or opened via `browser_open`. Changed the DevTools port assignment from a single fixed config value to per-screen: each screen picks a free 127.0.0.1 port at browser open time, eliminating port collision and the need to manually register agent-chrome MCP once per machine. Refactored browser opening to call a port allocator and check port ownership instead of checking if a port is free. Removed `browser.port` from config validation and the template; kept the file field to allow older config files to load without error. Added a new `internal/cdp/` package for Chrome DevTools protocol client over websocket with flattened sessions (no per-target session tracking). Added `internal/devtools/` with the Session type and the four tools, plus tests. DevTools tools check that the port is still held by the process that opened it, guaranteeing they never reach the human's own Chrome.

Bumped plugin version to 0.5.0 to invalidate the cached 0.4.0 plugin on machines running the skill, forcing a refresh that picks up the devtools tools.

## Sub-project B: desktop control

Built control of the human's own Hyprland desktop on branch `feat/desktop-control`. The spec is `docs/superpowers/specs/2026-09-30-hyprcage-desktop-design.md`, the plan is `docs/superpowers/plans/2026-09-30-hyprcage-desktop.md`, and every ruling is in `docs/superpowers/specs/2026-09-30-hyprcage-desktop-rulings.md`.

- `screen: "desktop"` works on `screenshot`, `snapshot`, `find`, `act`, `click`, `double_click`, `move`, `scroll`, `drag` and `app_launch`. The new tools are `desktop_workspace`, `notify_list`, `notify_act` and `notify_wait`.
- `act` on the desktop tries AT-SPI first, then CDP, then the real pointer or `send_shortcut`. The pointer path puts the cursor back after each action.
- `hyprcage notifyd` runs as the user unit `hyprcage-notifyd.service`. It keeps 48 hours of notifications in `~/.local/state/hyprcage/notifications.jsonl` (mode 0600). It rests at about 12 MB RSS.
- Tests run on a nested Hyprland on the hidden workspace `special:hyprcage-e2e` (`tests/nested-hypr.sh`), with a headless output at 1920x1080 scale 1.5. Notification tests run in `dbus-run-session`.

Findings:

- Hyprland 0.56 needs `xdg_wm_base` version 6. cage, weston and sway offer version 5 only, so a nested Hyprland runs only inside Hyprland.
- The host window of the nested Hyprland does not render on a hidden workspace, so the nested instance needs a headless output.
- `wl.Client.OutputSize` gives 960x540 at scale 1.5. Absolute pointer motion is proportional over the logical layout, so the desktop pointer uses the logical layout as its extent.
- AT-SPI extents of GTK3 and Qt windows are relative to the window. The desktop source adds the window position.
- AT-SPI `DoAction` does not open a Qt menu-bar menu on Wayland, so a menu-bar title gets a pointer click.
- swaync can invoke an action only on the latest notification, and its action index skips the `default` key.

Result: `tests/e2e-desktop.py` passes 10 steps and skips 1 (the lock refusal needs hyprlock). It uses 1 screenshot. The human's workspace and cursor did not change during the run.
